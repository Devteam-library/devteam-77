# Contributing to Devteam-library

Спасибо за интерес к проекту! Ниже — правила, которые упрощают ревью и поддержку кода.

## Как предложить изменение

1. Сделайте fork репозитория и создайте ветку от `main`:
   `git checkout -b feature/короткое-описание`.
2. Внесите изменения. Старайтесь, чтобы один PR решал одну задачу —
   так его проще проверить.
3. Убедитесь, что тесты проходят локально (см. ниже).
4. Откройте Pull Request с понятным описанием: что изменено и почему.

## Локальная разработка

```bash
git clone https://github.com/Devteam-library/devteam-77.git
cd devteam-77
python3 -m pip install -e ".[dev]"
pytest
```

## Стиль кода

- Публичные функции и классы должны иметь docstring в том же стиле,
  что и остальной код (описание, `Args`, `Returns`, `Raises`).
- Новая функциональность должна сопровождаться тестами в `tests/`.
- Именование, форматирование и импорты — придерживайтесь того,
  что уже принято в соседних модулях.

## Формат коммитов

Проект использует [Conventional Commits](https://www.conventionalcommits.org/):
`feat: ...`, `fix: ...`, `docs: ...`, `refactor: ...`, `test: ...`, `chore: ...`.
Это позволяет автоматически строить changelog модулем `devteam_library.git_utils`.

## Сообщить об ошибке

Откройте Issue с шагами воспроизведения, ожидаемым и фактическим поведением.
Если возможно — приложите минимальный пример кода.

## Кодекс поведения

Будьте уважительны к другим участникам. Конструктивная критика — да,
переход на личности — нет.
